# 毕业七年，我重新打开了毕设项目——从 CNN 到 CRNN 的验证码识别之路

前端开发牛马，毕业七年后重新复习毕设项目。还能回到朝气蓬勃充满希望的时光吗？

打开那个 GitHub 仓库的时候，我连 CNN 卷积的具体过程都记不清了。七年业务开发，深度学习的知识已经原封不动还给了老师。但这次不一样——上学时照猫画虎，工作后要深度理解。借助 AI 工具，重新搞懂这个项目，顺便优化一版。

## 一、项目原貌——七年前我是如何实现验证码识别的

七年前做毕设，思路很朴素：验证码是多个字符拼在一起的，那就先切开，再一个一个认。

整个流程：

1. `captcha` 库生成带噪声的验证码
2. 灰度化 → 二值化 → 八邻域降噪
3. 轮廓检测找字符边界，粘连的用滴水算法再切一次
4. 每个字符 resize 成 25×40，丢给 CNN 做 26 分类（a-z）

### 图像预处理

#### 灰度化：把彩图变黑白

验证码是彩色的，但识别用不到颜色信息——字符和背景的区分靠亮度，不靠色彩。灰度化就是 RGB 三通道合成一个通道，0~255 表示明暗。一行代码的事：`img.convert('L')`。

#### 二值化：非黑即白

灰度图还有 256 个灰度级别，处理起来太复杂。设个阈值，亮的变白（255），暗的变黑（0），只剩两种颜色。

阈值怎么选？我当时用的是全图平均灰度值。不是什么精妙算法，但对于这种简单验证码够用了。

二值化之后字符纯黑、背景纯白，很干净。但噪声点也变成了黑点——下一步处理。

#### 八邻域降噪：剔除孤立噪点

二值化之后，图片上散布着黑色噪点。这些噪点有个特征：孤立的，周围 8 个邻居大多是白色。

做法就是看每个黑色像素周围的 8 个邻居，白色邻居超过阈值 N（比如 5 个）就判定为噪点，变白。可以重复多轮。

```
  白 白 白
  白 ● 黑     → 6 个白邻居 >= 5 → 噪点 → 变白
  白 白 白
```

我还实现了另一种方式：看中心像素和邻居的颜色**是否一致**。和 8 个邻居都不一样，大概率是噪声。

实际用的时候 N 设多少、跑几轮，需要根据验证码的噪声程度调整，两轮下来基本能清理干净。

#### 轮廓检测：找到每个字符的边界

噪声清完了，下一步用 OpenCV 的 `findContours` 做边缘检测，找到所有连通的黑色区域，`boundingRect` 框成矩形。宽度 10~159、高度大于 20 的才要——太小的框是残余噪点，接近全宽的框是图片外边框，都过滤掉。

框出来按 x 坐标排序，理想情况下 4 个字符正好 4 个矩形。

#### 滴水算法：切开粘连的字符

轮廓检测能解决大部分情况，但碰到字符粘连就不够用了——两个字符挨太近，会被框成一个大矩形。需要二次分割。

二次分割我用了两个算法配合：先用**垂直投影法**找到分割的起始位置，再用**滴水算法**画出具体的分割路径。

**垂直投影法**：对要分割的区域统计每列有多少个黑色像素，得到一个直方图。两个字符之间的缝隙，直方图上会出现明显的低谷——黑色像素最少的列就是最可能的分割位置。

**滴水算法**（Drop Fall Algorithm）：从垂直投影找到的起始位置开始，模拟一滴水从粘连区域顶部往下流。水滴每一步看周围 5 个邻居的黑白情况，根据权重决定往哪个方向走（左下、正下、右下）。水滴从顶流到底，走过的路径就是分割线。

三个字符粘在一起（宽度超过 60 像素且只剩两个区域），就找两条分割线，切成三份。

这个算法花了我不少时间。碰到边界怎么处理、路径重叠怎么去重——全是调出来的。水滴每一步看 5 个邻居（左上、左下、正下、右下、右上），根据黑白情况计算权重决定方向。如果走到死胡同，还要处理回退和边界限制。复杂度比前面几步加起来都高。

最后每个字符 resize 到 25×40，丢给 CNN。

### CNN 模型

这次重新打开项目，我打算把 CNN 原理从头啃一遍。当年是照猫画虎跑通了就完事，这次要搞懂每一步在干什么。

CNN 全称"卷积神经网络"，干两件事：**卷积层提取特征，全连接层做分类。** 从第一层卷积开始拆。

#### 第一层卷积：从像素到特征图

输入是一张 40×25 的灰度图——每个像素 0~255 的数字，0 是黑 255 是白，形状 `(40, 25, 1)`。

卷积核是个 3×3 的小矩阵，9 个权重。具象看就是 9 个数字排成方阵，抽象看是一个"扫描器"——在图片上滑动，找特定图案。

做法很简单：3×3 窗口放在图片左上角，窗口覆盖的 9 个像素和卷积核的 9 个权重一一相乘，加起来得到一个数。然后窗口右移一格，再来。扫完整张图，得到一张"特征图"。

```
第1步：左上角 9个像素 × 9个权重 → 求和 → 1个输出值
第2步：右移一格 → 再来 → 又1个输出值
...
扫完 → 一张特征图
```

特征图是什么？一张和原图差不多大的矩阵，但每个位置的值不再是"像素亮度"，而是"这里有没有卷积核想找的图案"。值越大，匹配越好。

32 个不同的卷积核，就是 32 种扫描器。扫完得到 32 张特征图，叠在一起形状 `(40, 25, 32)`。

但这里有个有意思的事——卷积核初始值是**随机**的。一开始扫出来的特征图就是一团乱，本质就是一堆混乱的数字矩阵。

经过一轮轮训练，卷积核的值慢慢变了。往哪个方向变？"让预测更准"的方向。具体变成什么样，模型自己决定。训练完之后，有的卷积核变成了横线检测器，有的变成竖线检测器，有的找角点——不是人工设计的，是模型自己学出来的。

这些特征后面全连接层会拿去用。全连接层的权重里，就藏着"怎么解读这些特征"的钥匙。

我做了个交互式 Demo，可以单步播放看卷积核怎么滑动：**[卷积过程可视化 Demo](convolution-demo.html)**

#### 第二层、第三层：从特征到更高级的特征

第二层的输入不再是像素了，是第一层输出的 32 张特征图。

关键细节：第二层的每个卷积核不是只看 1 张特征图，而是同时看全部 32 张。形状 `(3, 3, 32)`——在每个位置，把 32 张特征图同一个 3×3 区域的值乘以各自权重，**全部加成一个数**。

这个"加权和"就是组合。每个通道贡献一个简单特征的强度，权重控制"这个特征重不重要"，加在一起判断复杂特征存不存在。

🌰 第 1 通道检测到"这里有竖线"，第 5 通道检测到"这里有右弯弧线"，第 17 通道检测到"上下有连接"——把这些信号组合起来，可能判断"这里有个字母 b 的局部"。

层层看下来：

```
第1层：像素 → 横线、竖线、斜线、角点        （基础视觉元素）
第2层：线条 → 弧线、交叉点、直角转弯       （更复杂的形状）
第3层：弧线 → 字母的局部笔画               （开始有语义了）
```

**卷积能提取特征，是因为在做模式匹配；能组合特征，是因为深层卷积核同时看所有输入通道做加权求和。** 本质上同一个操作，只是输入从像素变成低级特征，输出就从低级特征变成高级特征。

#### ReLU、池化、Dropout

卷积出来的值有正有负。ReLU 就是负数变零，只保留正信号。没找到就是没找到，别拿负数凑热闹。

池化是 2×2 区域只保留最大值，特征图缩小一半。减少数据量，保留最显著的信号。

```
原始 4×4：             池化后 2×2：
┌──────────┐
│ 0.1  0.8 │ 0.3  0.2   ┌─────────┐
│ 0.3  0.5 │ 0.1  0.9   │ 0.8 0.9 │
├──────────┤             │ 0.7 0.6 │
│ 0.2  0.7 │ 0.4  0.1   └─────────┘
│ 0.6  0.4 │ 0.6  0.3
└──────────┘
```

Dropout 是训练时随机关掉 25% 的神经元，防止死记硬背训练数据。只在训练时开。

#### 反向传播：模型怎么学会的

前面说的是"前向传播"——数据从输入流到输出，得到预测。但光预测没用，模型得知道自己猜对了还是猜错了，然后调整自己。这就是反向传播。

**算误差。** 模型输出 26 个分数，真实标签是 `e`，但模型可能给 `c` 打了 2.1 分、给 `e` 打了 0.3 分。交叉熵算出一个 loss 值——错得有多离谱。

**往回传。** 从输出层开始反推，每个权重对这个 loss 有多少"责任"。这个"责任"就是梯度——损失函数对权重的偏导数。

```
前向传播：输入 → 卷积 → 池化 → 全连接 → 输出 → loss
反向传播：loss → 输出 → 全连接 → 池化 → 卷积 → 输入
```

**更新权重。**

```
新权重 = 旧权重 - 学习率 × 梯度
```

学习率控制步子大小。太大震荡，太小收敛慢。Adam 优化器自动调，不用手动管。

反复做：前向算 loss → 反向算梯度 → 更新权重 → 再前向……几千轮下来，预测越来越准。

本质就是**链式法则**——复合函数求导，一层一层往回乘。每层只需要后一层传过来的梯度，乘上自己的局部梯度，再往前传。所以不管网络多深，计算量都是线性的。

#### 全连接层：拍板做决定

三层卷积做完，128 张 5×4 的特征图，总共 2560 个数值。要的不是特征，是答案——这个字符到底是 a 还是 b 还是 c？

Flatten 展平成一维数组，2560 个排成一列。然后两层全连接：

```
2560 个特征值
      ↓  Dense(1024)  加权和 + 偏置 + ReLU
   1024 个中间值
      ↓  Dense(26)    加权和 + 偏置
   26 个得分
```

"全连接"就是每个输出都和**所有**输入相连。第一个 Dense 层有 2560×1024 = 262 万个权重。

为什么两层？一层只能学线性关系。加个隐藏层中间插 ReLU，能学非线性关系——比如判断 `b` 要同时满足"左边有竖线**且**右边有圆圈"，两个条件单独看不够，得组合。

最后输出 26 个得分，最高的就是预测结果：

```
[a=-0.3, b=0.1, ..., e=2.8, ..., z=0.2]
                          ↑
                      最大值 → 预测 'e'
```

#### 当年的模型结构

```
Input (40, 25, 1)
  → Conv2D(32, 3×3) → MaxPool → Dropout
  → Conv2D(64, 3×3) → MaxPool → Dropout
  → Conv2D(128, 3×3) → MaxPool → Dropout
  → Flatten → Dense(1024) → Dropout
  → Dense(26)
```

274 万参数，训练 880 步，验证集准确率 99%。

#### 原来的方案有哪些问题

借助 AI 分析，问题很清晰了：

**分割是最大瓶颈。** 整个流程里分割占了我大部分精力。灰度阈值、降噪参数、轮廓筛选条件、滴水算法的方向权重——每一步都靠手动调参，而且只对特定类型的验证码有效，换个噪声风格参数就得重来。泛化能力不行。

**错误累积。** 单个字符 99% 的准确率看着不错，但四个字符组合起来 0.99^4 ≈ 96%。加上分割环节的误差，整体掉到 85% 以下。

（毕业论文和答辩 PPT 上我可不敢这么写🐶）

**固定长度。** 只能识别 4 位验证码，换长度就没辙。

## 二、v2.0 CRNN + CTC 端到端识别

这次回来直接换思路：**别分割了，整张图丢进去识别。**

CRNN（CNN + RNN）是 OCR 领域经典架构，配上 CTC Loss，端到端训练序列识别模型。不需要分割，不需要逐字符标注，图片进去，文字出来。

### 新模型结构

```
Input (60, 160, 1)  ← 整张验证码，不分割
  → Conv2D(32) → BN → ReLU → MaxPool
  → Conv2D(64) → BN → ReLU → MaxPool
  → Conv2D(128) → BN → ReLU → MaxPool
  → Conv2D(128) → BN → ReLU → MaxPool
  → Permute → Reshape (40, 384)  ← 宽度当时间轴
  → BiLSTM(64) → BiLSTM(32)      ← RNN 学字符序列
  → Dense(27, softmax)            ← 26 字母 + 1 空白
  → CTC Loss / CTC Greedy Decode
```

CNN 提取特征序列，BiLSTM 理解字符间上下文关系，CTC 把输出对齐到文字。不用手动切字符，模型自己学。

### 支持变长验证码

v1 只能识别固定 4 位。v2 用 CTC，天然支持变长序列。生了一批 3-7 位不等的训练数据加进去，模型照样学。

### 测试结果

跑了 1008 张测试图，各种长度和噪声：

| 指标         | 结果                  |
| ------------ | --------------------- |
| 准确率       | **98.2%**（990/1008） |
| 平均推理耗时 | 42.6ms（GPU）         |
| 错误样本     | 18 张                 |

错误集中在 4 位和 6 位样本上，多数是相似字符混淆或长序列末尾丢字符。

### v1 vs v2 对比

|            | v1.0 (2019)               | v2.0 (2026)             |
| ---------- | ------------------------- | ----------------------- |
| 架构       | 分割 + CNN 单字符分类     | CRNN + CTC 端到端       |
| 输入       | 25×40 单字符图            | 60×160 整张验证码       |
| 长度       | 固定 4 位                 | 3-7 位变长              |
| 分割       | 需要（轮廓检测 + 滴水法） | 不需要                  |
| 准确率瓶颈 | 分割质量                  | 序列对齐                |
| 框架       | TensorFlow 1.15           | TensorFlow 2.15 / Keras |

CRNN 在验证码这个场景上优势太明显了。砍掉分割这一步，就砍掉了最大的不确定性。
